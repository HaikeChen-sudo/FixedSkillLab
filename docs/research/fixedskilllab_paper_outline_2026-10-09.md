# 固定 Skill 的收益边界：强检索基线、实际加载与执行成本

论文式提纲与摘要草稿｜2026-10-09

## 定位与使用范围

本文拟写成实证研究，不提出新 Router，不将 T 型结构或正文索引本身列为原创方法。研究对象是本项目的人工固定 Skill、交互环境与执行协议。它整理一条证据链：早期的收益观察经过强基线检查、实际加载核对和内容消融后，哪些解释还能成立，哪些必须收回。

这是提纲，不是已完成论文，也不代表新颖性或投稿条件已经满足。[主张—证据表](fixedskilllab_claim_evidence_2026-10-09.md)是写正文时的约束；正、负结果使用同一标准，不因不利结果而删去实验。

## 摘要草稿

固定 Skill 可以为大模型 Agent 提供可复用的过程指导，但检索命中、实际加载和最终执行收益并不是同一个问题。我们整理 FixedSkillLab 在交互环境中的多阶段对照实验，并复核模型实际收到的 Skill、环境成功判定和累计执行成本。ScienceWorld 的旧批次显示固定指导相对无 Skill 的局部收益，而 ALFWorld 的结果没有呈现同方向的稳定改善。进一步加入 BM25 与预训练语义检索后，已保存查询上的 Top-3 命中差距被消除。在六题语义 Top-3 实验的 18 个配对中，12 个加载提示完全相同；总体 Token 节省不能直接解释为正文索引选出了更有用的内容。后续四题内容消融全部成功，但没有一个实例同时减少预先规定的两项动作指标，未复现移动措辞的机制假设。上述结果限定了本项目对 Skill 收益的解释范围，也说明同任务配对、实际加载记录和失败实验的完整披露是必要的。现有证据不支持正文检索的一般优势，亦不足以确认一个新的选择或执行算法。

关键词：固定 Skill；交互式 Agent；检索评估；执行成本；可复现性。

## 1. 引言：将问题限定为收益及其归因

第一段说明实际问题：加入固定指导会增加输入，也可能减少错误探索。需要同时问任务是否完成、完成所需的总开销是否改变，不能用 Skill 长度或单次输入代替 episode 成本。

第二段区分三层变量：检索器给出的排序、给 Agent 的完整有序文本、Agent 与环境交互产生的轨迹。排序变化未必改变加载内容；加载内容变化也未必改善任务完成。

第三段交代研究是逐步形成的：早期批次用于发现，后续协议分别冻结；本文对全部阶段的解释属于回顾性综合，不声称整个项目有一个从头执行到底的预注册计划。

拟回答的问题：

- RQ1：固定指导在本项目所测设置中呈现什么收益与代价？只作各批次内部对照。
- RQ2：改用较强检索基线后，原有命中差距及其执行收益解释是否保留？
- RQ3：两种检索方案是否让模型收到不同文本；相同与不同文本配对分别贡献多少观察到的成本差额？
- RQ4：对局部动作现象提出的单句内容假设，是否通过新开发实例上的预定判据？

拟保留的贡献表述是可复核的实证材料、分层归因审计和未复现结果。它们的学术增量仍需与相关工作比较，不能把工程产物数量当作贡献强度。

## 3. 实验材料与分析方法

### 3.1 环境、Skill 与 Agent

解释任务输入、工具动作、环境反馈和终止规则。Mini Lab 是管线验证背景；主结果分别讨论 ALFWorld 和 ScienceWorld，不把不同任务空间、Skill 库、预算和提示当成一个统一随机实验。

模型请求名为 `deepseek-v4-flash` 不等于掌握了服务端权重指纹。相同 temperature 也不保证输出逐字一致。报告每批实际记录的模型名、日期、环境版本、库版本、Agent／控制器版本与预算，缺失项明确标注。

### 3.2 批次角色与样本单位

| 批次 | 角色 | 分析边界 |
| --- | --- | --- |
| ALFWorld v5、v8 | 收益边界的对照材料 | 各批次分别分析；v8 是定向 Oracle，不冒充 Router 对比 |
| ScienceWorld v11b | 旧哈希检索下的局部正结果 | 18 个实例，各重复三次；不是强语义检索验证 |
| ScienceWorld v13b | 内容联合消融 | 复用已见六题，同时改变 Procedure 与 Termination；不能估计单字段效应 |
| 强语义 Top-3 六题 | 实际加载与执行收益核对 | 六个实例，54 个 episode；跨任务沿用的协议差异需披露 |
| Top-1 四题开发诊断 | 局部现象发现 | 题目受已见排名影响，不是盲测确认 |
| 四组内容消融 | 预定动作机制的开发检验 | 四个新 dev 实例，48 个 episode；全部绕过 Router |

不相加独立题目数：同一 task-variation 在不同阶段复用时，必须保留重叠关系。统计配对至少使用批次、任务实例、重复编号和条件；不能只按任务名合并。

### 3.3 六项主指标

| 指标 | 正文口径 | 需要披露的限制 |
| --- | --- | --- |
| Task Success Rate | 成功 episode 数／完成 episode 数；列出分子、分母 | 成功由环境判断；传输异常与任务失败分开 |
| Input Tokens | episode 内全部已记录模型调用的输入 Token 之和 | 包括重复发送的历史，不等于 Skill 长度 |
| Output Tokens | episode 内全部已记录模型调用的输出 Token 之和 | 未记录的中断请求不可补零 |
| Total Tokens | Input＋Output，逐条对账 | Token 不是 FLOPs，也不是实际能耗 |
| End-to-End Latency | 新记录用 `runner_ms`，注明计时边界 | 旧批次没有完整字段则记“未记录”，另列原 `latency_ms`，不得改名顶替 |
| Cost per Successful Task | 包括失败在内的总估算费用／成功数 | 无成功为未定义；冻结价格估算不等于实际账单 |

每个结果表保留六项，不因某项不利而省去。工具调用、环境 moves、得分、拾取命令数和路由时间仅作补充。本文不再引入新的综合效率分数。

### 3.4 比较和不确定性

先按实例汇总重复，再检查配对方向。mean ± std 明确是三次重复的组均值波动，不写成置信区间。已有任务簇区间引用原分析并注明抽样单位，不把反复探索后的显著性当预注册验证。

同提示配对不是完整输入相同的保证：需区分加载文本哈希、初始观察和后续历史。缺失观察哈希保留未知。把相同／不同提示的 Token 差额分解视为算术归因检查，不视为因果中介估计；不得因差额出现于同提示组就断言其来源必然是模型随机性。

## 4. 结果：按证据问题组织，不按版本流水记账

### 4.1 收益并未跨所测设置稳定复现

对应主张 C1。保留 ScienceWorld v11b 的正结果和 ALFWorld v5／v8 的边界结果。只解释批次内差异，不下“ScienceWorld 比 ALFWorld 更适合 Skill”的因果结论。详细六项表复用已审计来源，旧时延另列。

### 4.2 更强基线削弱了原检索机制解释

对应 C2。展示同一历史查询集上 Hash、BM25 与 MiniLM 的 Gold 命中对比；离线结果不能填进在线成功率列。小候选库、Top-3 覆盖比例和重复题面要一起披露。

### 4.3 实际加载内容相同，也会观察到较大成本差异

对应 C3。强语义六题和 Top-1 四题分别展示同集合、同顺序、同提示的数量；给出逐题 Token 差额及两类提示配对的贡献。两组同样失败的省 Token 不能称为提高了完成任务效率。

### 4.4 单句动作机制没有通过预定判据

对应 C4。列出四组的全部六项指标，以及逐题调用数、拾取命令数和判据结果。明确 0/4 达到联合减少要求；纠正“新实例只变盒子颜色”的旧描述。它否定本轮复现判断，不否定所有同房间直接移动场景。

## 5. 测量问题与有效性威胁

Procedure holdout 和 T1–T3 放在这一节或附录，说明早期假设为何停止，而不是为它们重新寻找正向表述。Procedure 评分器对别名、消歧和物体类别的误读属于测量缺陷；事后修正只能标为诊断，不能替代原预定评价。

必须保留的威胁包括：任务与 Skill 经多轮开发、只有一个模型请求系列、服务端版本不可控、部分测试实例已用于后续分析、条件顺序和缓存状态的影响、极端长轨迹对均值的影响，以及原始日志和公开快照的覆盖不一致。

环境成功与过程服从并列。任务允许短路径时，不执行 Skill 的推荐过程不自动构成错误；没有充分状态或路径证据时，也不能把预算内失败直接标为 Procedure 不可行。

## 6. 讨论与结论

讨论只回答：哪些局部观察可保留、哪些机制解释已经被限制、之后的研究需要什么更强证据。不在讨论末尾承诺一个尚未实现的动态选择算法，也不把“未来可以研究”当成本稿贡献。

结论的候选句：本项目观察到固定指导在部分任务设置中的收益，但强检索基线和实际加载审计削弱了将这些收益归于正文检索的解释；局部动作机制也未通过后续开发判据。固定 Skill 的价值需要在具体任务、内容与执行协议下评价。
