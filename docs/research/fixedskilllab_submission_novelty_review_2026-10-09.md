# FixedSkillLab 投稿增量审查

日期：2026-10-09。对象：[中文完整初稿](fixedskilllab_paper_draft_2026-10-09.md)。本次只审查研究问题与先例的关系，不改正文、数据或协议，不运行实验。文献范围限定为 SRA-Bench、Skill Following、SkillSeek 和 Agent Skills Can Be Harmful 的指定 v1 原文；不是穷尽性查新，也没有独立复现这些论文。

## 1. 判断

当前材料有实证与复核价值，但我不建议把它直接定位为已经具备充分新增量的独立通用实证论文。已有工作覆盖了收益不稳定、检索与使用脱节、正文索引未必更好，以及额外流程引发成本等宽命题。将这些命题换到 ALFWorld 和 ScienceWorld，不能单独证明研究增量。

最值得保留的是实际加载审计：一个看起来支持 Body 节省 Token 的汇总结果，其净节省并不来自加载不同提示的配对。这是具体、可检查的反例。它能否成为独立论文的中心，需要区分两件事：现在已经有一个本地反例；尚未证明这种归因失配在其他实验中稳定存在、达到何种规模或能由某套新评估方法可靠纠正。当前更稳妥的定位是可复核的审计案例与技术报告，而非新检索方法或通用机制研究。这个判断不等于否定负结果的发表价值，也不预测任何投稿结果。

## 2. 四个研究问题逐项判断

| 问题 | 先例已覆盖的部分 | 本项目仍可保留的窄增量 | 当前能否独立承担主贡献 |
| --- | --- | --- | --- |
| RQ1：固定指导的收益与代价 | SRA 已报告收益依赖模型、任务和加载方式；Harmful 已对正确性与成本退化进行对照分析。 | 在本项目这些冻结批次中，同时保留 ScienceWorld 局部正结果与 ALFWorld 成本边界，提供另一组环境下的可复核材料。 | 目前不能。跨批次的模型服务、预算、库与任务组成不同，尚未识别收益边界由哪个因素决定。适合作为背景证据，而非“发现 Skill 并不总有效”。 |
| RQ2：强基线是否保留旧命中差距 | SRA 比较词法与语义检索；SkillSeek 比较标准 IR，并直接做索引文本消融。 | 本地六候选库中，旧 Hash Flat 的漏检在 BM25/MiniLM 下消失；修正此前对正文必要性的解释。 | 目前不能。它纠正本项目弱基线，不是对已有强方法的新挑战。Hit@1 差异仍存在，Hit@3 饱和也不代表一般等效。 |
| RQ3：同提示与异提示如何贡献执行成本差额 | SRA 分离检索、加载和执行；Skill Following 已将汇总差异按实际检索事件分层，并提出同任务配对。 | 按实际有序 Skill 提示哈希审计 Flat/Body；在六实例数据中，异提示配对没有贡献净 Token 节省。同提示不等于检索事件相同，二者不是同一个分层。 | 最接近可发展的主张，但目前证据仍不足。它是小样本历史归因检查，不是新因果估计器。未在这四篇的已核查部分发现完全同样的审计，不构成“首次”证明。 |
| RQ4：单句动作机制是否跨新开发实例成立 | Skill Following 已有空内容、无信息、错配和破坏内容对照；Harmful 已分析流程诱发的额外动作。 | 按既定门槛保留 0/4 未通过记录，说明由厨房内局部路径推导的解释没有通过新起点实例检验。 | 目前不能。负结果对这条具体假设有效；“允许直接移动”并非“强制直接移动”，新起点又可能需要跨房间拾取，不能升级为一般的过程指导无效结论。 |

上述先例覆盖依据见下一节。表中的“不能”针对当前独立主贡献的强度，不要求每个实证结果都必须提出新算法。

## 3. 定向原文核查

### SRA-Bench：概念分解与加载控制已有先例

原文 §2 分开定义检索、纳入上下文与应用；§5.2 在 Gold 始终存在时加入困难负例并打乱顺序，对比全文注入和渐进披露；§5.3 比较 BM25、TF-IDF、BGE 等。因此，“命中不等于有益使用”和“需要强检索基线”都不能作为本项目的新命题。[SRA v1 §2、§5.2–5.3](https://arxiv.org/html/2604.24594v1)

### Skill Following：汇总效果与实际使用的差别已有量化研究

原文 §3 用同任务有／无 Skill 配对，并分开整体与实际检索子集的结果；§4.4 包含空返回、无信息填充、随机与破坏内容。其分层依据是检索事件，不是两检索器之间逐字相同的加载文本。当前审计应明确这一窄区别，不能只说“我们关注实际使用”。[Skill Following v1 §3、§4.4](https://arxiv.org/html/2609.00549v1)

### SkillSeek：比现有草稿写出的关系更直接

除 BM25 与两阶段检索外，§4.3/Table 2 已对比名称加描述、再加入截断正文、以及 Tool-REX 标签。正文加入并未在该设置改善成功率。因此它直接涉及本项目的索引字段问题，不宜在相关工作中只归为“采用强 IR 的先例”。其大候选库、正文截断与加载接口又不同，不能把它当作本地六候选库结果的复现。[SkillSeek v1 §4.3/Table 2](https://arxiv.org/html/2609.38822v1)

### Harmful：成本退化与轨迹归因已有先例

原文 §III-A 采用同任务、验证器、Agent 和环境条件下的 Skill 对照；§V 分开上下文膨胀与流程增加造成的成本。其效率退化定义要求两边成功，本项目最大的同提示节省却出现在两边均失败的斜面题。这是应披露的比较边界，不是直接胜过该文的证据。[Harmful v1 §III-A、§V](https://arxiv.org/html/2608.11888v1)

以上是对指定版本内容的核查，不认可或复述这些论文自己的全部首创性、因果性或泛化声明。

## 4. 对最强候选主张的压力测试

本地[内容结题与语义证据复核](scienceworld_content_closeout_2026-10-08.md)保存了关键分解：18 个 Flat–Body 配对来自六个实例，其中 12 对提示相同；全部 Flat−Body Token 差额为 269,283，同提示贡献 405,223，异提示贡献 −135,940。

这一结果足以反驳本批次的特定解释：“汇总节省就是 Body 选出了更省成本的指导”。但以下几个更强版本仍不成立：

- 不能写“正文检索没有因果效果”。同提示和异提示分组对应不同任务，分组内差额不是随机分配处理后的效应估计。
- 不能写“成本优势已证明全由模型随机性造成”。旧批次没有初始观察哈希，也未识别全部服务状态与执行差异。
- 不能写“Body 提高了失败题完成效率”。同提示差额最大的斜面实例两边均失败，少消耗只表示支出较少。
- 不能把“相同 Skill 提示”简写为“输入完全相同”。任务外其他消息、隐藏状态和后续历史并未由这个哈希全部覆盖。

因此可以保留的贡献句是：“我们公开一个交互式 Agent 检索比较的审计案例：分组检查实际加载后，汇总 Token 优势不支持原内容选择解释。”它比“固定 Skill 的收益边界”更窄，但与材料强度匹配。算术分解本身很简单，独立论文的分量必须来自问题的实际重要性、可靠控制与可迁移证据，而不是给该分解起新名字。

## 5. 稿件取舍与停止条件

若当前停止新增实验，建议以审计案例和可复核技术报告收尾：RQ3 居中，RQ1–RQ2 交代为何需要审计，RQ4 作为没有支持替代解释的结果。984 条记录可说明归档范围，不能替代独立任务数量或用来证明统计把握度。七批迭代过程的完整性有工程和复核价值，但迭代数量不等于七项研究贡献。

若用户仍希望向独立实证论文推进，先解决一个证据门槛，而不是立即扩跑：能否构造此前未用于挑选的固定任务块，在冻结模型与执行协议、记录完整初始请求和实际 Skill 提示后，对检索条件与提示匹配的重放条件分别比较，从而辨别检索选择变化与同提示重复运行差异。需要预先说明何种结果会推翻候选主张，且不能只保留会产生相同提示或有利差额的题。

这只是条件性设计要求，不是已批准的新实验，也不保证做完就有论文。即使再出现同提示差异，也可能只确认 Agent 本来具有运行波动；若不能证明该审计对某个具体研究结论有实质影响，就不应继续靠扩大样本寻找“新机制”。

本轮没有修改现有论文或执行脚本。新颖性判断与数据正确性审查分开；本文件引用已有本地复核结果，未声称重新逐条验算全部 984 条记录。
