# 固定 Skill 检索与执行的实证审计：实际加载、成本差额与未复现记录

中文技术报告｜2026-10-09 修订

本版依据投稿可行性审查修订论述，保留原文件路径和全部主表。修订前审查对应的稿件指纹见[审查记录](fixedskilllab_submission_audit_2026-10-09.md)；该记录是历史快照，不是对本版的重新验收。

## 摘要

本报告核查固定 Skill 检索比较中的实际加载内容与执行成本，回顾 FixedSkillLab 在 ALFWorld 和 ScienceWorld 中的七个实验批次，共 984 条完成记录。报告保留成功率、输入与输出 Token、总 Token、完整端到端时间和每成功任务费用；各批次任务、协议及运行时间不同，不合并估计总体效果。ScienceWorld v11b 中，Body 相对无 Skill 的成功率由 42/54 提高至 48/54，平均总 Token 减少 66.6%，但相对 Flat 的净 Token 节省集中于少数实例；ALFWorld 对照未呈现同方向的稳定收益。对历史查询加入 BM25 与 MiniLM 后，Flat 和 Body 的 Top-3 Gold 命中差距被消除。语义 Top-3 在线实验的 18 个 Flat–Body 配对中，12 个加载相同 Skill 提示，异提示配对反而增加了 Body 的累计 Token。一道两组均失败的斜面题贡献的节省超过全批净差额。后续四组固定内容消融均成功 12/12，但没有一个实例达到同时减少调用与拾取命令的预定要求。上述记录支持局部效果描述，却不足以将汇总成本优势归于正文索引选出了更有用的指导。报告提供一个可复核的加载审计案例，并保留未通过的动作解释；不提出新检索算法，也不声称固定 Skill 普遍有效或无效。

关键词：固定 Skill；交互式 Agent；检索评估；实际加载；执行成本

## 1. 引言

为 Agent 提供一份任务相关指导，可能减少搜索和试错，也可能引入额外阅读、无关步骤或错误约束。即使任务最终完成，也需要核对整个 episode 的消耗：多轮历史反复进入模型输入时，短文本并不必然对应低成本，较长指导也可能因缩短执行轨迹而降低总 Token。本文研究的是这种设置依赖的收益，而不是 Skill 文本越丰富是否越好。

这个问题有两类比较。第一类是有 Skill 与无 Skill 的比较，检验固定指导在给定任务、模型和预算下是否有净收益。第二类是不同选择方式之间的比较，检验正文索引相对名称与描述索引是否带来额外收益。第一类成立不能自动支持第二类：如果两种检索器给模型加载相同文本，它们的执行差异就不能直接解释成一方选到了更有用的内容。

我们将检索排序、实际加载的有序文本和最终执行轨迹分别记录与检查。排序上的 Gold 命中只回答人工指定候选是否出现，不回答候选本身是否正确、其他文本是否干扰，或者模型是否按指导完成任务。实际加载核对则检查方法名称背后是否形成了不同的文本干预。只有明确这些区别，在线成功率与成本差异才有可解释的比较对象。

本文围绕四个问题展开：

- 研究问题 1：固定指导在所测批次中呈现哪些收益与代价？
- 研究问题 2：加入较强检索基线后，旧 Top-3 命中差距是否保留？
- 研究问题 3：观察到的执行成本差异，有多少来自加载相同或不同 Skill 提示的配对？
- 研究问题 4：从局部轨迹提出的单句动作机制，能否通过后续开发实例上的预定判据？

本报告以研究问题 3 的实际加载审计为中心；问题 1–2 交代局部收益与基线检查，问题 4 记录后续动作解释未通过开发判据。七批完成记录是材料规模，不是 984 个独立任务，也不是一次统一设计的大样本试验。方法与结果按批次展开，讨论只归纳这些记录能够支持的认识。

## 2. 相关工作

### 2.1 交互环境与本研究的范围

ALFWorld 将文本环境中的抽象策略与 ALFRED 的具身任务对齐；ScienceWorld 提供面向科学推理的交互式文本任务。本文使用其文字交互接口，研究额外固定指导对执行的影响，不复现环境论文中的训练方法，也不声称改进整个基准上的最优结果。[1](https://arxiv.org/abs/2010.03768v2) [2](https://arxiv.org/abs/2203.07540v2)

### 2.2 检索命中与实际使用

Skill Retrieval Augmentation for Agentic AI 的受控实验保持 Gold Skill 在候选中，改变困难负例数量和顺序，并比较全文注入与渐进披露。Skill Following 使用有／无 Skill 配对，区分总体效果与发生检索的子集，还设置空返回、无信息文本和破坏内容等对照。这些工作已覆盖“找到 Skill 不等于获得执行收益”的重要部分。[3](https://arxiv.org/html/2604.24594v1) [4](https://arxiv.org/html/2609.00549v1)

本文不以这一概念区分本身为创新。我们的材料补充的是本项目中实际加载文本与成本差额的核对：当两个检索条件给模型相同 Skill 提示时，执行差异不能仅凭方法名称归于更好的内容选择。这个检查与上述控制思想相关，不是新的因果估计器。

### 2.3 强检索基线

SkillSeek 在较大规模 Skill 检索中比较标准信息检索方法，并研究检索与重排。其 §4.3、Table 2 还直接比较了名称加描述、再加入截断正文 `body[:800]`，以及 Tool-REX 标签三种索引文本；加入正文没有在该设置中提高任务通过率。因此，正文索引的收益边界已有直接消融先例，不能只将该文归为强检索基线工作。该消融使用 34K 候选池与不同执行模型，正文截断和加载接口也不同，不能把其胜负直接套用于本项目。[5，§4.3/Table 2](https://arxiv.org/html/2609.38822v1)

本文加入 BM25 和 MiniLM 是基线检查，不是新检索器，也不主张首次比较元数据与正文索引。当前小库上的 Hit@3 饱和也不能推断大规模库中的 Flat 与 Body 等效；本地结果仅限制旧哈希基线下的解释。

### 2.4 激活决策与潜在负收益

SkillApt 利用同任务 WITH／WITHOUT 执行证据支持激活或放弃加载，并区分适用条件失效时的隔离处理。Agent Skills Can Be Harmful 则报告固定指导引发的任务退化和额外成本。选择是否加载与识别 Skill 负收益已有直接先例。[6](https://arxiv.org/html/2609.26863v1) [7](https://arxiv.org/html/2608.11888v1)

本研究没有实现新的激活学习方法，也不将失败案例本身视为创新。与这些工作相比，本文集中于一条已完成实验链中的归因变化：旧结果呈现局部收益，强基线削弱正文索引解释，实际加载审计进一步限定成本归因，随后内容假设未通过开发判据。这条证据链有复核价值，但尚未证明同类归因问题在其他模型或实验中稳定存在。

## 3. 研究设计与测量方法

### 3.1 研究对象与比较范围

本研究考察人工固定 Skill 对交互式大模型 Agent 的任务完成与执行成本的影响。Agent 接收任务和环境观察，通过大模型选择工具动作，再将执行反馈写入后续上下文。Skill 是额外加载的指导文本，包含名称、描述、激活条件、执行过程和终止条件。成功由程序或环境判定，不由模型自行评分。

实验在 Mini Lab、ALFWorld 和 ScienceWorld 上分阶段开展。Mini Lab 用于检查工具调用、数据记录和自动判分管线，不进入本文主要效果比较。ALFWorld 与 ScienceWorld 的任务空间、Skill 库和执行协议不同，各批次分别分析，不将所有 episode 合并计算一个总体效果。

本文是回顾性证据综合。部分后续实验保存了执行前协议、任务清单和文本指纹，但整个项目并非从开始就按一个统一预注册计划执行。后续协议中的开发判据按原文评估，不能用本次整理替换历史判据。

### 3.2 条件定义

No Skill 不加载 Skill。All Skills 加载当批候选库的全部文本。Flat 与 Body 的区别在检索索引：Flat 使用名称与描述，Body 使用完整 Skill；选中后，二者通常都给 Agent 加载完整文本。因此，Flat 不等于“Agent 只看元数据”。

Oracle 使用人工指定的 Skill，排除自动选择这一环节，但不保证内容正确、模型遵循或任务完成。Oracle 不能直接视为其他条件的数学上界。Metadata、Placebo 和固定内容组是独立的内容干预，应与检索条件分开解释。

早期 ScienceWorld 检索使用有符号哈希向量。后续离线审计加入 BM25 和本地预训练 MiniLM，在线实验再比较语义 Flat 与语义 Body。不同实现的同名 Body 条件不能直接合并；方法标识至少包含检索器、库版本、加载条数和执行协议。

### 3.4 指标与数据纳入

设某条件有 N 条完成记录，成功指示为 s_i，输入与输出 Token 分别为 I_i、O_i，已记录估算费用为 c_i。六项主指标定义如下。

表 2　六项主指标及计算口径

| 指标 | 计算口径 |
| --- | --- |
| Task Success Rate | Σs_i/N，同时列成功数与完成数 |
| Input Tokens | ΣI_i/N；每条记录已累计该 episode 内各次模型请求的输入 |
| Output Tokens | ΣO_i/N；每条记录已累计输出 |
| Total Tokens | Σ(I_i＋O_i)/N，逐行验证输入、输出与总量一致 |
| End-to-End Latency | 有完整记录时使用平均 runner_ms，换算为秒 |
| Cost per Successful Task | Σc_i/Σs_i，包括失败记录的费用；零成功时未定义 |

Input Tokens 包含多轮重复发送的历史，不等于 Skill 的长度。Total Tokens 是计量代理，不等于 FLOPs 或实际能耗。费用使用当批冻结价格和缓存记录估算，不等于账单；中断或重试后未落盘请求的支出不在完成记录中。

新批次的 `runner_ms` 覆盖环境创建至关闭，不含批量预检。旧 `latency_ms` 的计时边界较窄，本文单独列为“原计时”。ALFWorld v5、v8 和 ScienceWorld v11b、v13b 没有保存 `runner_ms`，对应完整时间列标为“—”，不作插补。因部分记录没有逐阶段等待时间，不能把慢 episode 全部解释成模型推理或网络问题。

本文使用保存的环境成功字段。ScienceWorld 同时核对 success 与 score≥100 一致；ALFWorld 沿用环境完成判定，不用最终自然语言回答推断成功。网络异常和中断记录不等于任务失败；本文分母只涵盖计划中已保存的完成 episode。失败和慢运行均保留，不以成功运行子集计算主表。

### 3.5 配对与解释规则

记录唯一键为运行标识、任务实例、重复编号和条件。方法间按相同实例与重复编号配对，机制判据先对同实例的三次重复求均值，再比较实例方向。三次重复的组均值标准差只描述运行波动，不是置信区间。本稿不新增显著性检验，不把均值差异写成已确认的总体效应。

实际加载审计分别比较 Skill 集合、有序列表和提示文本哈希。相同集合不保证相同顺序；相同 Skill 提示也不保证环境隐藏状态或后续上下文相同。语义 Top-3 缺失初始观察哈希，保留未知；后续 Top-1 和固定内容实验可核对观察文本一致，但这仍不能证明全部隐藏状态一致。

Token 差额按同提示和异提示配对分解，仅用于检验解释是否与实际干预相符，不是因果中介分析。同提示仍有差异，说明不能仅凭该差异认定检索选出了更好的指导；它不自动证明差异全由随机性造成。

本版补充逐实例的成本集中度诊断。先汇总同一实例各条件的三次重复，再计算 Flat−Body 的累计 Total Tokens 差额；某实例的贡献比例为其差额除以全批净差额。其他实例存在反向差额时，该比例可以超过 100%。这是事后影响诊断，不是预注册检验，不改变全样本主表，也不据此删除长轨迹或失败实例。

## 4. 结果

各表的 Input、Output、Total 均为每 episode 平均 Token，时间单位为秒，费用单位为美元。表内数值独立四舍五入，显示值相加可能有 0.01 的误差；原始行均通过 Token 加和检查。完整时间缺失不代表零。

### 4.1 收益方向依赖具体批次

ScienceWorld v11b 中，Body 比无 Skill 多成功 6 次，成功率高 11.11 个百分点，平均 Total Tokens 少 66.6%；Flat 位于两者之间。这是旧检索器、该库与该任务集下的观察，支持局部效果描述，不能直接证明正文索引优于强 Flat 基线。

平均收益并未覆盖多数实例。相对 Flat，Body 在 18 个实例中只有 5 个的平均 Total Tokens 更低，另 13 个更高。全批 Flat−Body 累计净差为 7,290,080 Token，`boil:v027` 一题贡献 8,111,240，占净差的 111.3%；其余 17 题合计为 −821,160，即 Body 消耗更多。这是影响诊断，表 3 仍包含全部实例。

成功差额也有集中性：Body 相对无 Skill 多出的 6 次成功来自 `boil:v027`、`freeze:v027`、`freeze:v028` 和 `find-living-thing:v232` 四个实例；相对 Flat 多出的 3 次成功只来自两个 boil 实例。该批有汇总收益，但不能据此称优势已跨任务稳定复现。

ALFWorld v5 未呈现相同方向。All Skills 比无 Skill 多成功 1 次，但 Token 和估算费用更高；Body 比无 Skill 少成功 3 次，Token 更多。BM25 Body 与无 Skill 同为 88/90，但也有额外消耗。不能只保留有利条件而称所有 Skill 方案有效。

离线审计对保存查询、候选库与 Gold 标签保持不变，重算四种检索方法。v3 库只有六条候选 Skill，Top-3 已覆盖候选的一半。48 个分析单元对应 36 种库内查询原文，不应称为 48 个独立问题。

### 4.4 单句移动指令没有通过开发判据

## 5. 讨论

### 5.1 局部收益不能替代选择机制的证据

ScienceWorld v11b 与 v13b 表明，固定指导在部分所测设置中与更高完成率和更低累计消耗并存。ALFWorld 的结果又显示，额外加载可能只有成本，没有观察到完成率收益。两个方向都应保留。用某一批胜负给 Skill 整体定性，会遗漏任务组成、内容质量、模型能力与执行协议的影响。

Oracle 也需要这一限制。人工指定候选只移除了自动检索的不确定性，未消除内容缺陷或执行错误。在 ALFWorld v8 中，Oracle v7 与无 Skill 都成功 60/60，但前者平均 Total Tokens 更高。这意味着该批没有观察到额外指导的净成本优势，并不意味着 Oracle 标签错误，更不能证明其他任务不需要指导。

本项目没有把环境、内容、模型和协议分别随机化，因而不能从跨批次方向不同推出其中哪个因素是原因。可以保留的结果是批次内部的配对观察；关于差异来源的判断必须服从对应控制条件。

### 5.2 排名变化是否传递到了模型输入

较强检索基线首先改变了对旧结果的解释。v3 库中，BM25 和 MiniLM 的 Flat 已能把 Gold 放进 Top-3，因此旧哈希 Flat 漏检不能继续用来论证正文索引的必要性。但 Top-3 全命中也不代表所有排序相同：候选顺序和另外两条 Skill 仍可能变化。

实际加载审计进一步表明，方法标签与模型收到的内容未必一一对应。语义 Top-3 中，Body 的平均 Token 较低，但同提示配对贡献的节省大于全部配对的净节省，异提示配对反而使 Body 消耗更多。这个分解不估计正文索引的因果效应；它指出的是一种归因不匹配：汇总表看起来有优势，不代表优势来自更好的内容选择。

同提示也不等于完整实验条件完全相同。后续历史、环境状态、服务端行为和运行顺序仍可能影响结果。本文没有识别这些来源各占多少。因此，“正文选择解释不足”与“已经证明是随机噪声”是两种不同判断，当前只能作前一种。

### 5.3 未复现结果约束了原动作解释

Top-1 诊断曾在两个非生物实例中观察到较少拾取，随后实验直接控制文本，检验“允许直接移动”相对“要求先拾取”能否减少动作。新四实例的起始房间不同，轨迹涉及跨房间搬运，正确组没有一个实例同时减少调用与拾取命令。按冻结规则，这一开发假设没有复现。

结果没有证明同房间直接移动不可用。它说明，从厨房内的局部路径推广到不同起点时，原解释缺少适用条件。后续不能把 0/4 改成只看某一项指标，也不能追加有利题目后沿用原判据称为确认成功。

四组均成功还带来另一项限制：错配内容没有造成完成率损失，不能因此认定模型忽略了全部指导；正确组成本较低，也不能认定收益只来自正确目标匹配。本实验没有独立干预每个文本字段，无法进一步拆开通用步骤、任务类别与执行选择的效应。

### 5.4 成功率、Token 与费用回答不同问题

成功率相同可以对应不同失败题，也可以对应不同成本分布。语义 Top-3 中，无 Skill 与两种检索的失败实例不同；如果只看 15/18，会掩盖任务层面的替换。两组都失败时少用 Token 可以减少支出，却不能表述为更有效地完成了该题。

Token、时间和货币费用也不应互换。Top-1 中，两种检索的成功率较高、每成功任务费用较低，但每 episode 的平均 Token 和完整时间高于无 Skill。缓存计价、输出比例和成功数都会影响费用比率；费用低不自动代表模型执行工作量少。现有记录只能支持这些指标各自的比较，不能折算成真实硬件计算量。

内容消融的时间长尾说明，少数慢运行可以改变条件均值。本文保留均值、中位数与原记录，而不是事后剔除长尾。没有逐阶段证据时，耗时来源保持未知。

## 6. 有效性限制

### 6.1 任务选择、重复使用与统计单位

本研究按已有证据链选择批次，不是项目全部运行的无选择总体汇总。早期结果影响了后续开发方向，部分题目与任务族被反复检查，Top-1 又是针对排序分歧选择的开发诊断。这些设计允许诊断具体解释，但不支持将条件均值当作整个 benchmark 的无偏估计。

三次重复没有增加独立实例数量，尤其四题、六题的后续实验不足以支持广泛外推。现有重复标准差只是运行波动；本稿不新增显著性或等效性声明。全成功也不能证明总体成功率为 100%。

### 6.2 实现、预算与模型服务

仅使用一个请求模型系列，未验证跨模型成立。不同批次的模型后台版本、执行日期、预算实现和控制器可能不同。强语义六题内部，各题条件共用对应 Agent，但不同任务族沿用不同协议；不能把任务间差异归于 Skill。

较早的预算字段没有分离 Agent 工具动作和环境 move，上限含义不完全一致。后续修正了记录方式，却不能倒推旧轨迹符合新的预算定义。本文保留批次边界，不用新字段替换历史事实。

### 6.3 测量与归因

成功判定依赖环境，但环境成功不等于过程服从。拾取计数只统计发出命令，也不判断动作是否必要。旧 Procedure 评分器出现过适用性误读，因此对应输出不能用作本稿的过程收益证据。

实际 Skill 提示哈希只能检查已记录文本。旧语义 Top-3 缺少初始观察指纹，无法保证配对状态完全一致。完整端到端时间在部分旧批次缺失；估算费用又不含未保存完整 episode 的部分请求。上述缺口限制了成本解释，不能靠当前默认配置或新运行补成历史记录。

### 6.4 文献范围与公开材料

相关工作部分是与本文命题对应的定向核查，不是穷尽性综述。SkillSeek 已有索引文本消融，其他近邻工作也已研究检索与使用脱节、内容对照和成本退化。本报告不声称首次发现这些现象，不把同提示审计包装成新算法。其局部审计案例尚不足以承担新方法或一般性效果论文的主张。

七批主表所用记录和分析入口可由附录定位。ALFWorld 两批的执行前计划与变更时间线仍需补齐；归档 manifest 只能证明文件身份，不能单独证明先登记后执行。Procedure holdout 尚缺独立公开原始快照，因此本稿不把它作为新增量化主结果。此前的提纲、分章草稿和冻结协议均保留，不被本稿覆盖。

## 7. 结论

本报告保留一个固定 Skill 检索比较的审计案例：按实际加载文本分组后，语义 Top-3 的汇总 Token 节省不支持“Body 选出了更省成本指导”的解释，且净差额主要由一道两组均失败的实例贡献。这个结论不识别运行差异的全部来源，也不能外推为正文检索没有效果。

其他批次提供该案例的背景和限制：ScienceWorld 保留部分完成率与成本改善，ALFWorld 显示额外指导可能增加消耗而不改善成功率；较强基线消除了当前历史查询的 Top-3 命中差距，后续单句移动指令也未通过开发判据。正结果、负结果与缺失字段均保留。当前产出是可复核的技术报告，不是新算法或固定 Skill 通用效果的证明。本轮开发实验链据此收尾，不追加运行以寻找有利结果。
