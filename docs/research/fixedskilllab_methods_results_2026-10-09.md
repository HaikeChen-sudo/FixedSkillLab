# 固定 Skill 的收益边界：方法与结果正文草稿

2026-10-09。本文对应[论文提纲](fixedskilllab_paper_outline_2026-10-09.md)中的方法与结果部分，主张编号沿用[证据表](fixedskilllab_claim_evidence_2026-10-09.md)。本次仅复算已有记录，不产生新实验结果。它不是完整投稿稿件，也不提出新的检索算法。

## 1. 研究设计

### 1.1 研究对象与比较范围

本研究考察人工固定 Skill 对交互式大模型 Agent 的任务完成与执行成本的影响。Agent 接收任务和环境观察，通过大模型选择工具动作，再将执行反馈写入后续上下文。Skill 是额外加载的指导文本，包含名称、描述、激活条件、执行过程和终止条件。成功由程序或环境判定，不由模型自行评分。

实验在 Mini Lab、ALFWorld 和 ScienceWorld 上分阶段开展。Mini Lab 用于检查工具调用、数据记录和自动判分管线，不进入本文主要效果比较。ALFWorld 与 ScienceWorld 的任务空间、Skill 库和执行协议不同，各批次分别分析，不将所有 episode 合并计算一个总体效果。

本文是回顾性证据综合。部分后续实验保存了执行前协议、任务清单和文本指纹，但整个项目并非从开始就按一个统一预注册计划执行。后续协议中的开发判据按原文评估，不能用本次整理替换历史判据。

### 1.2 条件定义

No Skill 不加载 Skill。All Skills 加载当批候选库的全部文本。Flat 与 Body 的区别在检索索引：Flat 使用名称与描述，Body 使用完整 Skill；选中后，二者通常都给 Agent 加载完整文本。因此，Flat 不等于“Agent 只看元数据”。

Oracle 使用人工指定的 Skill，排除自动选择这一环节，但不保证内容正确、模型遵循或任务完成。Oracle 不能直接视为其他条件的数学上界。Metadata、Placebo 和固定内容组是独立的内容干预，应与检索条件分开解释。

早期 ScienceWorld 检索使用有符号哈希向量。后续离线审计加入 BM25 和本地预训练 MiniLM，在线实验再比较语义 Flat 与语义 Body。不同实现的同名 Body 条件不能直接合并；方法标识至少包含检索器、库版本、加载条数和执行协议。

### 1.4 指标与数据纳入

设某条件有 N 条完成记录，成功指示为 s_i，输入与输出 Token 分别为 I_i、O_i，已记录估算费用为 c_i。六项主指标定义如下。

| 指标 | 计算口径 |
| --- | --- |
| Task Success Rate | Σs_i/N，同时列成功数与完成数 |
| Input Tokens | ΣI_i/N；每条记录已累计该 episode 内各次模型请求的输入 |
| Output Tokens | ΣO_i/N；每条记录已累计输出 |
| Total Tokens | Σ(I_i＋O_i)/N，逐行验证输入、输出与总量一致 |
| End-to-End Latency | 有完整记录时使用平均 runner_ms，换算为秒 |
| Cost per Successful Task | Σc_i/Σs_i，包括失败记录的费用；零成功时未定义 |

Input Tokens 包含多轮重复发送的历史，不等于 Skill 的长度。Total Tokens 是计量代理，不等于 FLOPs 或实际能耗。费用使用当批冻结价格和缓存记录估算，不等于账单；中断或重试后未落盘请求的支出不在完成记录中。

新批次的 `runner_ms` 覆盖环境创建至关闭，不含批量预检。旧 `latency_ms` 的计时边界较窄，本文单独列为“原计时”。ALFWorld v5、v8 和 ScienceWorld v11b、v13b 没有保存 `runner_ms`，对应完整时间列标为“—”，不作插补。因部分记录没有逐阶段等待时间，不能把慢 episode 全部解释成模型推理或网络问题。

本文使用保存的环境成功字段。ScienceWorld 同时核对 success 与 score≥100 一致；ALFWorld 沿用环境完成判定，不用最终自然语言回答推断成功。网络异常和中断记录不等于任务失败；本文分母只涵盖计划中已保存的完成 episode。失败和慢运行均保留，不以成功运行子集计算主表。

### 1.5 配对与解释规则

记录唯一键为运行标识、任务实例、重复编号和条件。方法间按相同实例与重复编号配对，机制判据先对同实例的三次重复求均值，再比较实例方向。三次重复的组均值标准差只描述运行波动，不是置信区间。本稿不新增显著性检验，不把均值差异写成已确认的总体效应。

实际加载审计分别比较 Skill 集合、有序列表和提示文本哈希。相同集合不保证相同顺序；相同 Skill 提示也不保证环境隐藏状态或后续上下文相同。语义 Top-3 缺失初始观察哈希，保留未知；后续 Top-1 和固定内容实验可核对观察文本一致，但这仍不能证明全部隐藏状态一致。

Token 差额按同提示和异提示配对分解，仅用于检验解释是否与实际干预相符，不是因果中介分析。同提示仍有差异，说明不能仅凭该差异认定检索选出了更好的指导；它不自动证明差异全由随机性造成。

## 2. 结果

各表的 Input、Output、Total 均为每 episode 平均 Token，时间单位为秒，费用单位为美元。表内数值独立四舍五入，显示值相加可能有 0.01 的误差；原始行均通过 Token 加和检查。完整时间缺失不代表零。

### 2.2 强基线消除了当前查询的 Top-3 命中差距

离线审计对保存查询、候选库与 Gold 标签保持不变，重算四种检索方法。v3 库只有六条候选 Skill，Top-3 已覆盖候选的一半。48 个分析单元对应 36 种库内查询原文，不应称为 48 个独立问题。

| v3 检索方法 | Flat Hit@1 | Flat Hit@3 | Body Hit@1 | Body Hit@3 |
| --- | ---: | ---: | ---: | ---: |
| 有符号 Hash 256 | 16/48 | 32/48 | 22/48 | 39/48 |
| 完整词频 | 16/48 | 32/48 | 10/48 | 48/48 |
| BM25 | 26/48 | 48/48 | 40/48 | 48/48 |
| MiniLM | 40/48 | 48/48 | 47/48 | 48/48 |

BM25 与 MiniLM 的 Flat、Body 均达到 Hit@3 全命中。按查询原文与 Gold 合并后的 36 个单元中，结论仍成立。MiniLM Body 的 Hit@1 较高，但首位排名、Top-3 覆盖率与在线执行收益是不同指标。该表对应 C2：旧哈希结果不足以支持“必须索引正文才能找到 Gold”。

此处没有运行 Agent，六项在线主指标均不适用，不能将检索编码器长度或 Hit@3 填入 Token、成功率列。设置与来源见[离线审计](scienceworld_retrieval_baselines_2026-09-24.md)。

### 2.3 实际加载审计限制了 Token 优势的解释

语义 Top-3 的三组都成功 15/18，但失败实例不同：无 Skill 在电路题三次失败，Flat 和 Body 在斜面题三次失败。相同汇总成功率不表示同题等效。

| 语义 Top-3 条件 | 成功率（成功/完成） | Input | Output | Total | 完整时间 | 每成功任务费用 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| No Skill | 83.33%（15/18） | 161,533.39 | 2,639.17 | 164,172.56 | 38.90 | 0.002574 |
| Flat | 83.33%（15/18） | 83,394.28 | 1,114.44 | 84,508.72 | 30.32 | 0.001505 |
| Body | 83.33%（15/18） | 68,461.72 | 1,086.83 | 69,548.56 | 29.52 | 0.001385 |

Body 的平均 Total Tokens 比 Flat 少 17.7%。但 18 个配对中有 15 个集合相同、12 个顺序相同、12 个提示哈希相同。Flat−Body 的全部 Token 差额为 269,283，其中同提示配对为 405,223，异提示配对为 −135,940。异提示部分反而增加了 Body 的消耗。

| 配对层 | 配对数 | Flat−Body 的累计 Token 差额 | 可作的解释 |
| --- | ---: | ---: | --- |
| 相同 Skill 提示 | 12 | 405,223 | 不能归于检索选择了不同指导 |
| 不同 Skill 提示 | 6 | −135,940 | 本样本中 Body 消耗更多 |
| 全部 | 18 | 269,283 | 两部分算术和，不是因果分解 |

差额最大的斜面实例，两组提示相同且均失败 0/3。该题平均 Total Tokens 为 Flat 261,016、Body 86,223；少消耗不能在这里解释成更高任务完成效率。记录缺失初始观察哈希，具体运行差异的来源仍无法完全分离。以上对应 C3。

后续 Top-1 开发诊断，两种检索均成功 12/12，无 Skill 为 9/12。提示相同的六对贡献 5,422 Token 差额，提示不同的六对贡献 8,238，总计 13,660。它留下了局部动作差异，但仍不支持将全部差额归于正文索引。

### 2.4 单句移动指令没有通过开发判据

固定内容实验绕过 Router，比较无 Skill、正确完整 Skill、错配完整 Skill，以及仅将第三步改为“必须先拾取”的文本。正确文本允许拾取或直接移动，并不强制模型直接移动。正确与先拾取组是单句对照；正确与错配组同时改变多处内容，不是单字段消融。

四组均成功 12/12。正确组比无 Skill 平均 Total Tokens 少 15.0%，但错配组与先拾取组也较低，无法将这一收益认定为正确匹配独有。

| --- | --- | ---: | ---: | ---: | ---: | ---: |
| No Skill | 100.00%（12/12） | 13,850.00 | 491.58 | 14,341.58 | 24.76 | 0.000464 |
| 正确 Skill | 100.00%（12/12） | 11,795.25 | 399.83 | 12,195.08 | 14.56 | 0.000386 |
| 错配 Skill | 100.00%（12/12） | 11,630.92 | 425.17 | 12,056.08 | 28.61 | 0.000405 |

拾取指标统计发出的命令，不表示每次动作成功，也不等于冗余动作。四实例的起始房间分别为温室、室外、铸造厂和客厅，不能沿用“只改盒子颜色”的早期描述。跨房间搬运可能需要拾取；这限制了将上一轮厨房中的现象推广到新实例的解释。按预定开发规则，本轮机制未复现，不因此否定所有同房间直接移动场景，也不追加有利实例来更改判据。

完整时间有明显长尾。先拾取组中有七次调用用时 191.46 秒、五次调用用时 155.01 秒的 episode；各组时间中位数依次为 15.09、10.54、12.70、12.83 秒。中位数与主表均值不同，慢值全部保留。缺少逐阶段证据时，不能因调用少就断言异常来自网络。逐次波动及轨迹解释见[内容结题报告](scienceworld_content_closeout_2026-10-08.md)。

ScienceWorld v13b 的完整指导组成功 15/18，元数据组为 7/18，安慰剂组为 9/18。完整指导在这批记录中同时有较低累计消耗，但该实验同时改变 Procedure 与 Termination，并复用已见六题。因此只能保留联合内容对照，不能称为 Procedure-only 效应或独立新题确认。

## 3. 解释范围与材料限制

现有结果支持三个有区别的判断。固定内容在部分任务上有局部收益；旧正文检索优势的解释受到强基线和实际加载审计限制；从局部轨迹提出的移动句机制没有通过下一轮开发判据。任何一项都不能替代另外两项，也不能由此推出固定 Skill 整体无效。

本文的限制直接影响外推：只有一个模型请求系列；任务、Skill 和协议经过多轮开发；部分实例被重复用于分析；小候选库使 Top-3 命中饱和；服务端版本、缓存和运行顺序不完全可控；旧日志缺少完整计时或初始观察信息。观察到的均值差异不能自动升级为总体因果效应。

ALFWorld 两批执行前计划与变更时间线尚需在方法附录补齐，归档哈希只能证明文件身份。Procedure holdout 的独立公开原始快照仍有缺口。本稿主表不依赖该批失效评分器，也不将待补材料写成已经完成的验证。不存在的历史字段保持缺失，不用新运行追补成旧事实。
