# FixedSkillLab 下一研究问题：先划清证据边界，暂不启动新方法实验

2026-10-08。本文是研究决策记录，不是实验协议。本次没有新增 episode，六项在线指标均不产生新数值；历史数字以各轮报告为准。

## 决定

目前没有一个候选同时满足“区别于已知工作、能由本项目客观检验、已有初步支持”这三个要求。因此不启动新的 Router、动态加载器或更大批量实验。下一份可交付材料应是现有结果的实证研究草稿，先判断它是否有足够的证据价值；不把工程实现、负结果或换名方案自动当成方法创新。

若用户仍以原创方法论文为目标，需要在提出实质不同的机制后另定研究范围。本文没有授权更换环境、训练模型或新增付费运行，也不承诺现有材料足以投稿。

## 一句话问题

**在这个固定人工 Skill 库与执行协议中，离线检索优势何时真正改变了模型收到的指导，而这些改变是否对应任务完成或成本收益？**

这是整理现有证据的问题，不是“首次发现检索不等于执行”。[Skill Following](https://arxiv.org/abs/2609.00549)已经用同任务有／无 Skill 配对评估实际使用收益；[SkillSeek](https://arxiv.org/abs/2609.38822)也已比较标准 IR 基线与复杂检索的任务表现及成本。本项目若写实证稿，必须正面讨论这些先例，不能用环境名称不同替代贡献论证。

## 候选裁决

| 候选 | 现有证据与最近先例 | 当前决定 |
| --- | --- | --- |
| 继续证明 Body-aware 比 Flat 好 | 本地强词法／语义基线已消除已见样本的 Top-3 命中差距；近期执行结果还存在大量相同加载提示。见[检索基线审计](scienceworld_retrieval_baselines_2026-09-24.md)与[结题复核](scienceworld_content_closeout_2026-10-08.md)。 | 暂停扩大；没有稳定的一般执行优势，也没有新算法。 |
| 检索后决定加载或不用 Skill | [SkillApt](https://arxiv.org/abs/2609.26863)已明确做 post-retrieval LOAD/ABSTAIN，并用配对 WITH/WITHOUT 执行证据学习适用边界。 | 不作为独立新颖点；仅加阈值或状态输入不够。 |
| 依据环境状态／预算判断 Skill 是否可执行 | [SayCan](https://say-can.github.io/)早已结合语义相关性与当前状态下的可执行性。其对象是机器人策略，不等于文本 Skill，但基础思想不是空白。本地[预算诊断](scienceworld_incline_budget_diagnosis_2026-09-24.md)也已提出这一疑点，不能重命名为新发现。 | 保留作局部诊断，不立刻训练选择器；尚缺事前可用的可执行性标签和跨实例支持。 |
| 审计 Procedure 是否被执行、是否增加不必要工作 | [Agent Skills Can Be Harmful](https://arxiv.org/abs/2608.11888)已比较配对轨迹，分析功能失败与过度过程带来的成本退化；本地[Procedure holdout](scienceworld_procedure_holdout_closeout_2026-09-22.md)还暴露了评分器与适用范围错误。 | 不以“首次发现过度步骤”立题；过程审计首先是测量工具，不能代替环境成功率。 |
| 检索、实际加载与执行收益的证据审计 | 已有方法研究覆盖了这一大问题；本项目有跨阶段记录、强基线复核和失败的机制验证，可以组织成有限范围的可复现实证材料。 | 只推进无 API 的写作与证据整理；不宣称创新已通过。 |

过程评测也不是空白：[Skill-Use](https://arxiv.org/abs/2608.04828)已经区分触发、流程遵循与操作边界，[SIGIL](https://arxiv.org/abs/2607.27309v3)将 Skill 流程编译为执行框架并分别评估遵循度与任务表现。因此“给 Skill 加状态校验”或“单独评分 Procedure”需要说明实质区别，不能只靠重新命名。

详细先例与重叠边界见[本次定向核查](fixed_skill_candidate_prior_art_2026-10-08.md)。有限检索无法证明某个窄区别没有先例。

## 草稿只保留四条可审查主张

1. **固定指导存在条件性的局部收益。** [主线证据审计](scienceworld_mainline_evidence_audit.md)保留了 ScienceWorld 旧批次的正结果；近期的负结果不能抹去这些观察。不同模型请求日期、预算、任务组成和 Skill 版本不得混池。
2. **原有收益不能直接归为正文检索机制。** 强基线改变了 Gold 命中的比较，实际加载提示相同的配对也出现了成本差异。这是归因限制，不是证明所有检索方法相同。
3. **局部动作差异未通过后续开发判据。** 四组内容消融的结果按原规则结题。跨房间搬运时“拾取”可能必要；不得因为未达到预期而改变判据或挑新题补正结果。
4. **环境完成、Procedure 遵循和经济成本必须分开。** 较短路径可能合法地完成任务，未执行 Skill 推荐步骤不自动算模型失败；遵循完整 Procedure 也不保证在预算内成功。必要步骤以任务和环境规则为准，不能用研究者偏好的流程改写成功条件。

以上是本项目范围内的观察与解释边界，不是四个新颖贡献。正文将并列保留正、负和未能识别机制的结果。

## 写作前的最低检查与停止条件

先做一张“主张—原始记录—协议—最近先例”证据表，复用已有分析，不再新建一套指标或评分器。每条主张标为观察、机制假设或未检验；保留六项指标：成功率、Input Tokens、Output Tokens、Total Tokens、完整端到端时延、每成功任务成本。旧数据没有完整计时边界时明确缺失，不伪造统一口径。

把同集合、同顺序、同提示哈希分开。相同提示的重复运行可以检查波动，却不是零效应的严格随机化对照；不同提示的事后分组也不能识别纯粹的检索因果效应。没有初始观察或模型版本指纹的旧记录，应标缺失而不是默认相同。

只有在证据表完成后，才判断是否值得写成完整论文草稿。如果全部结论只是已知现象的少量案例，或关键结论依赖失效评分器、事后选题和跨协议合并，则项目按可复现技术报告收尾，不继续为方法论文堆 episode。若发现新的可检验机制，须先说明与上述先例的实质区别，再冻结独立开发与确认计划。

T1–T3、Procedure holdout 和本次移动措辞消融的原停止决定保持有效。重开它们必须说明新增了什么外部证据或测量能力，不能仅以“换几道题再试”作为理由。

## 使用方式

下一步建议是写现有证据的论文式提纲与主张表，不运行新实验。是否以实证稿收尾或另立原创方法课题，需要在主张表上做决定。本文及文献核查可以提交 GitHub；不修改历史协议，也不把新写的判断追溯成实验前假设。
