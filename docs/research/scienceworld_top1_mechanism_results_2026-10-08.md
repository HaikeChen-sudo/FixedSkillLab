# ScienceWorld Top-1 开发诊断：成功率持平，正文检索的成本差异需拆分解释

运行标识：`scienceworld-top1-mechanism-dev-4x3`。分析日期：2026-10-08。

## 摘要

本轮完成四个官方 dev 实例、三种条件、三次重复，共 36 个 episode。No Skill 成功 9/12，Semantic Flat Top-1 和 Semantic Body Top-1 均成功 12/12。全部失败来自同一个生物任务实例的三次重复；在该实例上，Flat 和 Body 加载了完全相同的 Skill。

Body 的平均 Total Tokens 比 Flat 少 8.9%。按任务类型分开计算，39.7% 的总 Token 差额出现在两组 Skill 提示相同的生物任务中，不能归因于正文索引；60.3% 出现在检索结果不同的非生物任务中。非生物任务两组都成功，Body 六次均用三步完成，Flat 有五次多执行了拾取。该现象支持局部步骤节省的观察，尚不能证明正文检索的一般优势。

本轮是受已见检索结果影响的开发诊断，不是独立确认实验。暂不扩大批量运行，也不据此修改冻结 Skill。

## 1. 实验问题与控制

本轮检查离线 Top-1 排名差异是否转化为任务成功率、执行步骤或成本差异。

| 项目 | 固定设置 |
| --- | --- |
| 模型与采样 | `deepseek-v4-flash`，temperature=0，thinking disabled |
| 环境与预算 | ScienceWorld，simplification=easy；Agent 与环境上限各 100 |
| Skill 库 | 冻结 v3；运行期间不修改、不学习 |
| 检索器 | 本地 MiniLM；Flat 索引 Name＋Description，Body 索引完整 Skill |
| 加载方式 | 两种检索都仅加载第一名的完整 Skill |
| 任务与重复 | 四个 dev 实例，每题每组三次；组内位置轮换 |
| 客观判定 | 环境 score≥100 为成功，不由模型评价 |

两道非生物任务是离线排名分歧实例：Flat 选 `find-living-object`，Body 选 `find-nonliving-object`。两道生物任务是第一名相同的对照：两者都选 `find-living-object`。

逐条核验通过：36 条记录与冻结计划一致，无重复或缺失；成功字段与环境分数一致；输入和输出 Token 加和正确；实际加载文本哈希与冻结选择相符；控制器干预次数均为零。12 组 Flat–Body 配对的初始 observation 哈希相同，其中六组 Skill 提示哈希也相同。相同 observation 哈希不等于对环境全部隐藏状态的证明。

完整端到端时间使用 `runner_ms`，覆盖环境创建、reset、检索、模型调用、工具执行与环境关闭。不包含批量启动前的一次性预检。原汇总脚本的 `latency_ms` 不含环境创建与关闭，其组均值分别为 7.91、12.39、11.77 秒；两种边界不能混称。

费用沿用冻结的历史计价参数；缓存命中、输出长度和失败次数都会影响成本。36 条完成记录合计估算为 0.0117180084 美元，不代表供应商完整账单，也不包含未落盘请求可能产生的费用。

Input Tokens 是多轮请求累计输入，不是单次上下文长度，也不是 Skill 文本本身的 Token 数。成本和时延的组间差异也不能直接换算成推理计算量差异。

## 3. 逐题结果

表 2 每格为“成功次数/三次；平均工具调用数”。

| 任务实例 | No Skill | Flat Top-1 | Body Top-1 |
| --- | ---: | ---: | ---: |
| find-living-thing:v150 | 3/3；14.33 | 3/3；10.00 | 3/3；10.00 |
| find-living-thing:v151 | 0/3；3.00 | 3/3；12.00 | 3/3；11.33 |
| find-non-living-thing:v150 | 3/3；4.33 | 3/3；4.00 | 3/3；3.00 |
| find-non-living-thing:v151 | 3/3；4.00 | 3/3；3.67 | 3/3；3.00 |

### 3.1 No Skill 的失败集中在一个实例

`find-living-thing:v151` 的三个 No Skill episode 都在执行 `focus on potato` 后得到 score=-100 并终止。Flat 与 Body 都前往温室，选择 `pea plant` 并送入 green box，六次成功。

两种检索在这里加载相同的 `find-living-object`，Skill 提示哈希也相同。因此，观察支持“固定指导在这个实例上有帮助”，不支持“Body 检索提高了这里的成功率”。三次失败是一个任务实例的重复，不能写成三个不同任务失败。

No Skill 的平均分为 50，并非汇总错误：九次 100 分和三次 −100 分的均值为 50。失败运行三步就结束，也压低了 No Skill 的平均 Token 和时间，不能将这种低消耗称为完成任务更高效。

### 3.2 Gold 漏检没有在非生物任务上造成失败

Flat 在两个非生物实例上均加载 `find-living-object`，没有加载标注的 Gold；六次运行仍都选择秒表或打火机，成功将其移入指定盒子。Body 与 No Skill 在这两个实例上也都是 6/6。

观察到的动作差异是：Body 六次都为 `look around → focus → move`；Flat 五次为 `look around → focus → pick up → move`，一次为三步。不能从动作轨迹确定模型是否忽略了错误 Skill，或是否使用了其中可复用的步骤。

实际加载文本提供了一个待验证解释：生物 Skill 的第三步要求先拾取再移动；非生物 Skill 的第三步允许拾取或直接移动。这个差异与多余拾取现象一致，但本轮同时改变了多个文本字段，没有单独控制该句，不能确认为因果机制。

## 4. Token 差额的分解与时间代价

| 任务类型 | Flat 平均 Total Tokens | Body 平均 Total Tokens | 每次平均节省 | 占全部节省的比例 |
| --- | ---: | ---: | ---: | ---: |
| 生物：提示相同 | 20,619.83 | 19,716.17 | 903.67 | 39.7% |
| 非生物：提示不同 | 5,079.83 | 3,706.83 | 1,373.00 | 60.3% |

每种类型各有六对记录。全部差额为 13,660 Tokens，其中相同提示组贡献 5,422，不同提示组贡献 8,238。相同提示组的差额包含路线波动；例如同一实例不同重复中出现相反方向的绕路差异。它不能归因于 Skill 索引正文。

非生物六对记录中，Body 的 Total Tokens 六次都更低，五次少一次工具调用，一次调用数相同；平均 Token 降幅为 27.0%。这是已选两道 dev 实例上的描述性结果。六次重复并不是六道独立任务。

在这两个非生物实例上，No Skill 完整端到端均值为 5.69 秒，Body 为 8.05 秒，Flat 为 9.01 秒。Body 虽减少动作和 Token，仍未比 No Skill 更快。两种检索各 episode 都承担约 3.8 秒的本地冷启动路由时间。这是当前部署方式的真实代价；不能扣掉后再声称本轮端到端更快。未来若改为持久化检索服务，需单独编号测量，不能追改现有时间。

## 5. 结论范围

本轮未观察到 Body 相对 Flat 的成功率提升。固定 Skill 在一个生物实例上避免了重复发生的目标选择错误；正文检索在两个非生物实例上对应更短的执行轨迹，但标签匹配、文本措辞与模型运行波动尚未分离。

以下结论不受本轮支持：正文检索在 ScienceWorld 整体上更优；Gold 命中必然改善任务完成；Skill 普遍缩短端到端时间；该现象已经构成新的研究贡献。新颖性需要另行审查，本报告不作首创声明。

本轮仅含四个有针对性选择的开发实例、两个任务族。重复次数增加了运行波动的观测，没有增加独立题目数量。这里不报告显著性结论，也不将成功率相同解释为两方法等效。

## 6. 下一步：先固定一个可否定的内容机制问题

当前停止扩大这批 Top-1 任务。保存完整结果，包括失败，不为提高成功率重跑或删除数据。

若开展后续实验，应检验“正确内容是否有净收益，以及显式允许直接移动是否减少冗余拾取”。建议先写独立协议，再决定是否执行：

- 绕过 Router，直接比较无 Skill、正确完整 Skill、错配完整 Skill。它们回答内容匹配问题，不能冒充检索方法比较。
- 在正确完整 Skill 上另设最小文本消融，只替换第三步的移动指令，其余字段保持一致。它回答单句步骤约束问题；不把它称为通用 Skill 结构创新。
- 从尚未用于调参的官方 dev 实例中，按预先登记的规则选题；先核对历史使用记录，再冻结题号、文本、预算与分析标准。沿用环境反馈判分，不用模型自评。选择和修改阶段结束前不动独立 test 集。
- 记录六项主指标，另记录冗余拾取数、非法动作数、逐题成败和实际加载文本。若只降低步骤、没有可靠成功率差异，结论限于步骤成本；若跨新实例无法复现，则停止该机制方向。阈值、样本量与停止规则必须在运行前落实，不能看完结果后再定。

以上是下一轮设计建议，尚未冻结题号、实现新条件或启动 API。不要把现有结果用于声称后续实验已确认机制。
