# ScienceWorld 哈希检索碰撞审计

日期：2026-09-24。性质：已见题目的离线敏感性分析。本文比较检索排名，不新增 Agent 实验，也不修改历史成功率或费用记录。

## 结论

256 维哈希确实影响了部分 Gold Skill 的排名，但影响有两个方向。去掉哈希压缩后，11 个“题目 × 库版本 × 检索模式”组合从未命中变为命中，另有 2 个组合从命中变为未命中。不能只把碰撞解释成压低 Flat 的成绩。

最新斜面题 `v086` 的 Flat 漏检得到复现：Gold 排名从 256 维时的第 5 变为完整词频表示下的第 1。不过，旧 v3 库中 Flat 的 16 个漏检全部仍存在；同一批题目的 Body-aware 从 39/48 命中升到 48/48。旧数据中两种索引内容的差异没有因此消失，但这只是已见查询上的词法检索差异，不能直接推导新的 Agent 成功率。

## 数据范围与核验

来源是中央日志 `results/scienceworld_results.jsonl` 在本次审计时的 876 条记录，SHA-256 为 `c6590a3441532645afe4b3a61a38a6a38741d9cb2301456bb688a4b092184cb9`。

- 纳入全部 304 条 `retriever=hash-embedding-v1` 记录，未按任务成功与否筛选；其余 572 条未使用该检索器，不纳入。
- 逐条核对保存的 Skill 库哈希，并重放实际使用的检索模式。304/304 条的 Top-3 名称、分数、已加载 Skill 与 Gold 排名均与原记录一致。
- 按任务 ID、Skill 库版本/哈希、完整查询文本去重。合并 243 次重复测量后，得到 61 个分析单元，涉及 57 个任务 ID、49 个“库版本 × 查询原文”组合。合并不删除原 episode；不同 variation 也可能有相同题面，因此 61 不代表 61 个独立语言问题。
- 对每个分析单元都计算 Flat 和 Body-aware。某个版本只有 Body-aware 的在线日志时，表中的 Flat 是离线补算，不能当成该条件已有在线成绩。

五个 Skill 库分开报告。v3 的候选库只有 6 条 Skill，Top-3 已覆盖一半；v4 系列有 10 条。不同候选库、重复使用的题目和不同实验阶段不合并成一个总体成功率。本轮仅使用已保存题面，没有启动 ScienceWorld，也没有读取尚未运行的新题。

## 对照方法

沿用现有的小写正则分词、相邻二元词组、词频和余弦相似度，不改题面、Skill 文本、Gold 标签或候选集合。Flat 索引 Name 和 Description；Body-aware 索引完整 Skill，包括 Activation、Procedure 和 Termination，因此本对照不能单独识别 Procedure 字段的作用。

比较 256、1,024、4,096、65,536 四种有符号哈希维度，以及不做哈希压缩的完整词/二元组计数 `exact_counts`。后者是排查压缩失真的对照，不是预训练语义 embedding，也没有新增词干化或同义词处理。排序先比较未四舍五入的相似度，同分按 Skill 名称升序；只在输出时保留六位小数。

指标为 Gold Hit@1、Gold Hit@3 和 MRR（Gold 名次倒数的平均值）。维度检查沿用此前斜面单题诊断中的五种设置，本次全部报告；没有挑选最高的一档作为新的默认检索器。生产检索器仍保留原设置。

## 对现有研究结论的影响

斜面 `v086` 的在线结果仍是 No Skill、Body-aware、Oracle 成功，Flat 失败。离线对照只说明 Flat 本可在另一种表示下命中；没有新模型轨迹，不能把它改写成“修正后 Flat 成功”，也不能把原失败全部归因于碰撞或无关 Skill 干扰。

旧主线 v11b 的离线配对结果是：Flat 在 256 维和完整计数下均命中 12/18；Body 从 15/18 变为 18/18。因此，不能宣称此前正文索引的所有差异都是哈希假象。反过来，旧实验的 Agent 成功率也不能证明去掉碰撞后的新路由一定更好。完整计数改变的 Top-3 组合需要单独的执行实验，才能估计新的任务成功率与成本。

本轮没有新增 Task Success Rate、Input Tokens、Output Tokens、Total Tokens、端到端执行延迟或 Cost per Successful Task。Gold Hit@3 是检索指标，不能替代这六项在线指标。此次审计是查看既有结果后的诊断，不提供新的留出确认或算法原创性证据。

## 下一步与复现

建议把完整计数保留为后续实验的固定词法对照，避免继续围绕 256 维的偶然排名修改 Skill。若继续研究索引正文的作用，应先固定相同的 Flat/Body 文本、候选库与 Top-K，再分别接入 BM25 和预训练语义 embedding，在开发材料上检查后冻结新的确认协议。已经审计过的这些题目不能重新宣称为未见确认集。这里提出后续方案，尚未改在线路由或启动付费实验。

脚本只用 Python 标准库。可从已导出的源记录独立重放，无需 API Key、Java、ScienceWorld 数据包或完整 Agent 轨迹：

```bash
python3 scienceworld_hash_audit.py \
  results/scienceworld_hash_audit_2026-09-24/source_records.jsonl \
  --output-dir results/scienceworld_hash_audit_replay
```

输出目录必须尚不存在，以免覆盖已保存的审计。相同代码与源记录会得到相同的逐题排名；输入文件名称和来源摘要会因使用原日志还是导出记录而不同。

```bash
python3 -m unittest test_scienceworld_hash_audit -q
```

回归检查覆盖斜面漏检的复现、重复记录去重、库哈希和历史排名不一致时停止，以及导出后不依赖原轨迹的重放。
