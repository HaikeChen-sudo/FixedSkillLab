# ScienceWorld 固定内容消融结题与语义检索证据复核

日期：2026-10-08。主实验：`scienceworld-content-dev-4x3`。本次只分析已保存数据，未调用模型、环境或编码器。

## 摘要与决定

四组内容消融完成 48 个 episode，各组均成功 12/12。正确 Skill 相对“必须先拾取”文本，在四个实例中没有一道同时减少平均工具调用和拾取命令，未达到预先规定的至少三道题要求。本轮记为“机制未复现”，结束这一轮移动措辞验证，不追加有利题目、不重跑择优，也不改写原协议。

正确内容相对无 Skill 的平均 Total Tokens 降低 15.0%，但错配内容和必须先拾取组也降低消耗，不能把全部收益归因于正确内容匹配。这里没有成功率提升证据，更没有检索收益证据，因为四组都绕过 Router。

对既有语义检索实验的复核显示，六题 Top-3 实验的汇总成本差异主要需要用相同提示下的运行差异解释；四题 Top-1 实验只留下两道已选开发实例上的局部动作差异。当前材料不足以确立正文检索的一般执行优势。本结题不否定所有固定 Skill，也不作原创性声明。

## 1. 实验范围和校验

本轮只有一个任务族 `find-non-living-thing`，四个官方 dev 变体 v152–v155，每个条件重复三次。使用冻结的 DeepSeek `deepseek-v4-flash`、temperature=0、thinking disabled、easy 环境，Agent 和环境预算各为 100。成功仅由环境 score≥100 判定。

四组分别为无 Skill、正确完整 Skill、固定错配完整 Skill，以及只替换正确 Skill 第三步的“必须先拾取”版本。后两种移动措辞之外的对比并非单字段消融；错配 Skill 还改变了目标类别等内容。

逐条检查覆盖 48 个计划键、条件与提示哈希、Token 加和、终局分数、轨迹条数和拾取命令计数。无缺失或重复，所有记录的初始观察哈希均与相应冻结实例一致。哈希一致只证明已记录观察文本相同，不证明全部隐藏状态一致。控制器干预均为零。

原协议中的“准备阶段”保留为冻结时的历史状态，完成情况以本报告和原始记录为准。

### 对先前描述的更正

README 和对话曾把这些实例描述成“只改变目标盒子颜色”，这是不准确的。任务描述主要改变颜色，但初始观察中的起点分别是温室、室外、铸造厂和客厅。轨迹包含跨房间搬运，不能把拾取命令直接称作冗余动作。

这个错误不破坏同一实例内部的四组比较，但限制了机制解释：上一轮两个非生物实例从厨房出发，不能据此预期新实例同样可以省去拾取。新结果表示预定跨新实例判据未通过，不是证明同房间场景下直接移动无效。

### 重复波动和慢 episode

三次重复的组成功率均为 100%，标准差为零。这不意味着总体成功率为 100%，也不能据此判断方法等效。三次重复仍只有四道独立实例。

| 条件 | Total Tokens，mean ± sample std | 完整时间，mean ± sample std（秒） | 单 episode 时间中位数（秒） | 最长时间（秒） |
| --- | ---: | ---: | ---: | ---: |
| 无 Skill | 14,341.58 ± 1,780.79 | 24.76 ± 17.49 | 15.09 | 111.74 |
| 正确 Skill | 12,195.08 ± 2,366.83 | 14.56 ± 5.57 | 10.54 | 35.45 |
| 错配 Skill | 12,056.08 ± 1,165.82 | 28.61 ± 25.77 | 12.70 | 185.15 |
| 必须先拾取 | 11,260.67 ± 67.57 | 40.15 ± 49.09 | 12.83 | 191.46 |

mean ± std 基于三次重复各自的四题均值，使用 n−1 分母；中位数和最大值基于该条件全部 12 个 episode。它们是不同层次的描述统计，均不是置信区间。机器分析另存全部六指标的逐次统计。

必须先拾取组出现七次调用耗时 191.46 秒、五次调用耗时 155.01 秒的记录。少数慢运行明显影响均值，但当前证据不足以区分服务等待、网络重试等来源。原始记录全部保留，不事后剔除慢值。

## 3. 预先规定的机制判据

原协议要求：正确组相对必须先拾取组，至少三个实例同时减少平均工具调用和拾取命令，并且四个实例均不降低成功次数。

表 2 每格为三次重复的平均值；每题每组均成功 3/3。

| 实例 | 正确组调用数 | 先拾取组调用数 | 正确组拾取命令 | 先拾取组拾取命令 | 同时减少两项 |
| --- | ---: | ---: | ---: | ---: | --- |
| v152 | 7.00 | 7.00 | 1.00 | 1.00 | 否 |
| v153 | 5.00 | 5.00 | 1.00 | 1.00 | 否 |
| v154 | 8.67 | 9.00 | 1.00 | 1.00 | 否 |
| v155 | 12.67 | 11.00 | 1.67 | 1.00 | 否 |

最终为 0/4，低于要求的 3/4；平均调用数为正确组 8.33、先拾取组 8.00。不得将“没有成功损失”单独当成机制通过。

轨迹提供了与该结果一致的具体背景：v152 的 repeat 0 中，两组都执行“观察、聚焦铲子、拾取、去走廊、去厨房、观察、移入盒子”，均为七次调用。v153 的 repeat 0 中，两组也均先拾取室外的斧头，再前往厨房。v155 的正确组 repeat 0 先离开客厅，未携带书就尝试在厨房移动，失败后返回拾取，最终用了 16 次调用。这里只描述记录，不推断模型内部是否遵循某句提示。

## 4. 正确内容对无 Skill 的结果

正确组的平均 Total Tokens 比无 Skill 少 15.0%，前三个实例调用数较少，但 v155 的调用数和 Token 更多。错配组平均调用数同样为 8.33，Token 甚至略低于正确组；必须先拾取组平均 Token 最少。

因此可写成“这四道开发实例中，加载固定指导与较低的平均消耗并存”，不能写成“正确匹配独有地改善执行”。错误的任务类别没有阻止本轮错配组成功，也不能因此认定模型完全忽略了 Skill。

## 5. 回看既有检索实验：实际加载内容是否不同

本节仅复核两轮近期语义检索记录，不是项目所有历史实验的重新合并分析。不同轮次保持独立，不能把不同预算、任务组成和执行协议合并算一个成功率。

### 5.1 六题 Top-3：提示不同的配对没有贡献 Token 节省

`scienceworld-strong-confirm-6x3` 有六个实例、三组、三次重复，共 54 条记录。三组各成功 15/18，但失败实例不同：无 Skill 在电路题三次失败，两种检索在斜面题三次失败。相同成功率不等于成功于相同任务。

| 指标 | 无 Skill | Semantic Flat Top-3 | Semantic Body Top-3 |
| --- | ---: | ---: | ---: |
| Task Success Rate | 83.33%（15/18） | 83.33%（15/18） | 83.33%（15/18） |
| Input Tokens | 161,533.39 | 83,394.28 | 68,461.72 |
| Output Tokens | 2,639.17 | 1,114.44 | 1,086.83 |
| Total Tokens | 164,172.56 | 84,508.72 | 69,548.56 |
| End-to-End Latency，秒 | 38.90 | 30.32 | 29.52 |
| Cost per Successful Task，美元 | 0.002574 | 0.001505 | 0.001385 |

18 个 Flat–Body 配对中，15 个加载集合相同，12 个顺序相同，12 个提示哈希相同。具体区别如下，每题包含三次重复：

| 实例 | 实际干预区别 | Flat 平均 Total Tokens | Body 平均 Total Tokens | 两组成功数 |
| --- | --- | ---: | ---: | --- |
| chemistry-mix:v030 | 提示相同 | 85,979.00 | 126,277.67 | 均 3/3 |
| find-living-thing:v236 | 提示相同 | 27,618.33 | 24,479.00 | 均 3/3 |
| find-non-living-thing:v236 | 集合相同，前两条顺序互换 | 14,650.67 | 16,146.67 | 均 3/3 |
| grow-plant:v096 | 提示相同 | 86,904.33 | 89,463.67 | 均 3/3 |
| inclined-plane-determine-angle:v132 | 提示相同 | 261,016.00 | 86,223.00 | 均 0/3 |
| power-component:v018 | 首条均为电路 Skill，后两条组合不同 | 30,884.00 | 74,701.33 | 均 3/3 |

全部配对的 Flat−Body 总 Token 差额为 269,283。提示相同的 12 对贡献 405,223；提示不同的六对贡献 −135,940，即后者反而使 Body 消耗更多。这是算术分解，不是因果估计。提示相同情况下的执行差异不能解释为“正文检索选了更有用的指导”；最大的节省还出现在两组都失败的斜面实例上。

旧记录没有保存初始观察哈希，分析中保留 null，没有把两个缺失值判成状态一致。即使提示哈希相同，也不能假定完整输入历史相同。本节只复核已保存协议、加载文本和结果，不补造缺失状态信息。

### 5.2 四题 Top-1：保留局部观察，不升级为通用机制

`scienceworld-top1-mechanism-dev-4x3` 共 36 条记录。两种检索均成功 12/12，无 Skill 为 9/12。12 个 Flat–Body 配对中六个提示相同、六个不同；初始观察哈希逐对相符。

提示相同配对贡献 5,422 个 Token 差额，提示不同配对贡献 8,238，合计 13,660。后一部分来自两道非生物开发实例，曾观察到 Body 少拾取一步。四组内容消融正是为检查这一解释而做，本轮没有跨新实例复现。不能再把上一轮的局部观察写成已确认机制。

Top-1 的完整六项指标和轨迹解释见[原报告](scienceworld_top1_mechanism_results_2026-10-08.md)。原报告的“下一步”是当时计划，其完成结果由本报告补充，不修改原始分析数值。

## 6. 主线下一步与停止边界

主线仍是：固定 Skill 的加载内容与选择方式，在相同模型和预算下何时改善客观完成率或成本。内容、检索和 T 型结构是不同命题，不能互相代替。

目前结束“移动措辞普遍减少拾取”的开发支线，暂停扩大现有 Body-versus-Flat 实验。没有必要因为暂时没有正结果就换名字、扩库或继续寻找有利题目。

若继续研究，下一份工作应是一页研究命题与证据边界：明确已有实验支持哪些局部观察、强基线排除了什么，以及还剩哪个能被否定的问题。只有当该问题有独立意义、现有方法不能直接回答，并能设计出实际加载内容不同的受控对照时，才讨论新协议和付费运行。若没有这样的命题，就把项目整理为可复现评测与负结果记录，而不是继续声称新检索方法有效。本次没有重新做文献检索，不能给出新颖性通过结论。

本次不改 Skill、Router、Agent、冻结协议、题目清单或历史原始记录；不删除失败和慢记录。
